# User guide: map presentation and navigation

The repository produces two kinds of consumer data:

- GeoJSON for presenting and filtering discoveries on a map.
- GPX for handing an ordered ride selection to route planners and navigation apps.

GitHub and the canonical YAML files remain authoritative. Changes made in uMap,
Kurviger, Mapy.com, or OsmAnd are not synchronized back into the repository.

## App roles

| Goal | App | Input | Result |
| --- | --- | --- | --- |
| Browse all discoveries | uMap | Generated GeoJSON URLs | Persistent visual catalogue |
| Inspect the current selection | uMap | `generated/today.geojson` | Stops and selected road sections |
| Calculate an enjoyable road route | Kurviger | Repository GPX route | Motorcycle-oriented route |
| Navigate accurately and offline | OsmAnd | Final GPX track from Kurviger | Track guidance and offline fallback |
| Keep a simple mobile copy | Mapy.com | Final GPX track | Secondary display and navigation copy |

The GPX generated by this repository contains ordered route points. It does not
contain a complete road-following track. Kurviger should normally calculate that
track before it is imported into OsmAnd or Mapy.com.

## uMap: permanent overview

Create a map on a uMap instance such as
[umap.openstreetmap.fr](https://umap.openstreetmap.fr/). The initial setup works
on an iPhone but is easier on a larger screen.

### Places layer

1. Enter edit mode and open **Manage layers**.
2. Create a layer named `Places`.
3. Open the layer properties and select **Remote data**.
4. Enter this URL:

   ```text
   https://raw.githubusercontent.com/sanicek/local-rides/main/generated/places.geojson
   ```

5. Select `GeoJSON` as the format.
6. Select **Check URL** and verify that the features appear.
7. Leave **Use proxy** disabled. Enable it only if uMap reports a response or
   cross-origin error.
8. Save the map.

Useful presentation settings:

- Layer type: clustered when the number of discoveries becomes dense.
- Marker colour: blue.
- Popup title: `{name}`.
- Popup template:

  ```text
  # {name}

  Status: {status}
  Destination: {destination_score}/5
  Road: {road_score}/5
  Access: {motorcycle_access}
  Surface: {surface}

  {notes}

  {approach_notes}
  ```

### Roads layer

Create another remote layer named `Roads` using:

```text
https://raw.githubusercontent.com/sanicek/local-rides/main/generated/roads.geojson
```

Use an orange or red line with a width around 5. A useful popup template is:

```text
# {name}

Road score: {road_score}/5
Surface: {surface}
Access: {motorcycle_access}

{notes}
```

### Current ride layer

Create a remote layer named `Today` using:

```text
https://raw.githubusercontent.com/sanicek/local-rides/main/generated/today.geojson
```

Use a strong green colour. This layer contains the ordered destinations and
selected road geometry for the current ride.

Reload the uMap page after generated files change in GitHub. The uMap **Dynamic**
option fetches remote data again when the map is moved or zoomed; it is not a
timed refresh mechanism.

Available generated views:

```text
https://raw.githubusercontent.com/sanicek/local-rides/main/generated/places.geojson
https://raw.githubusercontent.com/sanicek/local-rides/main/generated/unvisited.geojson
https://raw.githubusercontent.com/sanicek/local-rides/main/generated/shortlist.geojson
https://raw.githubusercontent.com/sanicek/local-rides/main/generated/roads.geojson
https://raw.githubusercontent.com/sanicek/local-rides/main/generated/today.geojson
```

`shortlist.geojson` is a subset of `unvisited.geojson`. Enabling both produces
overlapping markers. Normal configurations should use either `Places + Roads`
or `Today` alone.

Reference: [uMap remote data documentation](https://discover.umap-project.org/fr/tutorials/10-embed-remote-data/).

## Kurviger: calculate the motorcycle route

Generate or download the GPX for the current selection. On an iPhone, if Safari
displays XML instead of downloading it, use **Share**, then **Save to Files**.

Open the [Kurviger planner](https://kurviger.com/en/plan) or Kurviger app:

1. Open the `...` menu.
2. Select **Import**.
3. Select **File** and choose the repository GPX from Files.
4. Select the named route in the import preview.
5. Confirm the import.
6. Verify the waypoint order against `selections/today.yaml` or the ride brief.

When a selected road segment is present, its two endpoints must remain
consecutive. They force Kurviger through the intended road section.

Recommended starting settings for a paved afternoon ride:

- Curvature: **Fast and curvy**.
- Avoid motorways: enabled.
- Avoid toll roads: enabled.
- Avoid unpaved roads: enabled.
- Avoid narrow roads: disabled.

Inspect every stop closely. A GPX point can represent a safe approach or parking
position rather than permission to ride directly to the object. Read the
canonical access notes or ride brief.

If Kurviger creates an unwanted detour:

1. Drag the route onto the intended road to create a shaping point.
2. Avoid shaping points directly on junctions and roundabouts.
3. Use **Snap all waypoints to the closest street** from the `...` menu.
4. Recheck the complete route.

References:

- [Kurviger route import](https://docs.kurviger.com/route_transfer/import)
- [Kurviger export best practices](https://docs.kurviger.com/route_transfer/best_practices)

## Export the final route

After the calculated Kurviger route is correct:

1. Open the `...` menu and select **Export**.
2. Select OsmAnd under **Navigation devices** when available.
3. Otherwise select GPX under **File format**.
4. Select **Track** as the main content.
5. Include the original via points when the option is available.
6. Inspect the export preview.
7. Select **Export route** and save the file to Files.

A track carries the exact calculated geometry. A route contains points between
which the receiving application calculates its own potentially different path.

Reference: [Kurviger route export](https://docs.kurviger.com/export).

## OsmAnd: offline and field navigation on iPhone

Before leaving:

1. Open **Menu > Maps & Resources** in OsmAnd.
2. Download the Slovakia map for offline use.
3. Find the final Kurviger GPX in the iPhone Files app.
4. Use **Share > OsmAnd Maps** and complete the import.

Start navigation:

1. Open **Menu > My Places > Tracks**.
2. Select the imported track.
3. Enable **Show on map**.
4. Select **Navigation**.
5. Use the motorcycle or car profile.
6. Open the **Follow track** settings.
7. Select navigation to the start of the track.
8. Start navigation.

If voice instructions are incomplete, use **Navigation > Settings > Follow
track > Attach to the roads**. Inspect the result before riding because road
attachment can alter poorly mapped or intentionally unpaved sections.

For gravel rides, retain the original GPX line as a visible reference and treat
road attachment cautiously. Current signs and barriers override all stored OSM
and repository information.

References:

- [OsmAnd track management](https://osmand.net/docs/user/personal/tracks/manage-tracks/)
- [OsmAnd GPX navigation](https://osmand.net/docs/user/navigation/setup/gpx-navigation/)

## Mapy.com: simple secondary copy

Import the final Kurviger-generated GPX rather than the preliminary repository
waypoint GPX.

In the iPhone app:

1. Log in.
2. Open **My Mapy**.
3. Select **Saved > Import GPX**.
4. Select the final GPX from Files.
5. Save it into a folder such as `Local rides`.

On the web, use **Tools > Import GPX**.

Use Mapy.com for quick inspection, tourist-map context, a secondary mobile copy,
and ordinary navigation. If Mapy.com recalculates the route, compare its line
with the Kurviger track, especially around deliberately selected road segments.

Reference: [Mapy.com GPX help](https://help.mapy.com/).

## Routine workflow

1. Inspect `Places + Roads` in uMap.
2. Put selected canonical IDs in `selections/today.yaml`.
3. Generate `today.geojson` and the repository GPX.
4. Check the selection visually in uMap.
5. Import the repository GPX into Kurviger.
6. Calculate, inspect, and stabilize the road route.
7. Export the result as a GPX track.
8. Import that track into OsmAnd.
9. Optionally import the same track into Mapy.com.
10. After riding, update canonical YAML statuses and observations, then regenerate
    the derived files.

## Reviewing an agent discovery pull request

A discovery pull request should contain two uMap links:

- **Proposed features only** loads the highlighted records added or modified by
  that discovery task.
- **With catalogue context** loads the catalogue at the PR merge base, its road
  segments, and the highlighted proposed records.

Both views are temporary browser maps backed by immutable GitHub commit URLs.
They do not modify or create a saved map in the reviewer's uMap account. Crimson
features are additions and dark-orange features are modifications. Review the
popup provenance, scores, and access confidence before merging. After merge,
the permanent remote layers obtain the accepted records from `main`.

The generated review links currently use Framacarte, which runs uMap and does
not require a login for an unsaved preview. This is independent of the saved
uMap account used for permanent catalogue layers.
